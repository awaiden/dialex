# h3 / Nitro

Für h3-1.x-Server: Nitro 2 sowie Nuxt-Serverrouten und -Middleware.

```ts
// server/middleware/dialex.ts (Nuxt / Nitro)
import { dialexH3 } from "dialexjs/h3";

import { dialex } from "~/dialex.generated";

export default dialexH3({ ...dialex });
```

```ts
// server/api/hello.get.ts
export default defineEventHandler((event) => {
  const dict = event.context.getDictionary("home");
  return {
    locale: event.context.locale,
    title: dict.title,
    subtitle: event.context.t("home.subtitle"),
  };
});
```

Die Middleware füllt `event.context.locale`, `event.context.getDictionary(name)` und `event.context.t` und setzt `Content-Language`, sofern `setHeader` nicht `false` ist. Alle [Optionen der Locale-Erkennung](../guide/locale-detection.md#options) gelten, und `custom` erhält das h3-Event.

::: warning Version
Gebaut und getestet mit h3 `>=1.8 <2`. h3 2.x hat eine andere API und wird noch nicht unterstützt.
:::

## Bewährte Vorgehensweisen

- Übergib `{ ...dialex }` aus `dialex.generated.ts` an den Adapter. Es enthält die Wörterbücher und die Locale-Konfiguration, sodass `defaultLocale`, `locales` und `fallbacks` nur einmal in `dialex.config.ts` stehen.
- Lege die Middleware in Nuxt und Nitro in `server/middleware/`, damit sie bei jeder Anfrage vor API-Routen und Renderern läuft.
- Verwende `event.context.t("home.title")` für einzelne Zeichenketten und `event.context.getDictionary("home")`, wenn du mehrere Schlüssel brauchst, damit die Zugriffe ein gemeinsam ermitteltes Locale nutzen.

## Fehlerbehebung

- **`event.context.getDictionary` ist undefiniert**: Die Middleware-Datei liegt nicht in `server/middleware/` oder exportiert keinen Standard-Handler.
- **h3 2.x wird nicht unterstützt**: Der Adapter zielt auf h3 1.x (Nitro 2 und Nuxt 3/4). Prüfe die h3-Version, die dein Framework installiert.
- **`[dialex] Dictionary "x" not found`**: Das Wörterbuch ist nicht in `dialex.generated.ts`. Führe `dx generate` aus und prüfe, ob `include` in `dialex.config.ts` zur Datei passt.
