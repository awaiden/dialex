# h3 / Nitro

Para servidores h3 1.x: Nitro 2, y las rutas y el middleware de servidor de Nuxt.

```ts
// server/middleware/dialex.ts (Nuxt / Nitro)
import { dialexH3 } from "dialexjs/h3";

import { dialex } from "~/dialex.generated";

export default dialexH3({ ...dialex });
```

```ts
// server/api/hello.get.ts
export default defineEventHandler((event) => {
  const dict = event.context.getDictionary("home");
  return {
    locale: event.context.locale,
    title: dict.title,
    subtitle: event.context.t("home.subtitle"),
  };
});
```

El middleware rellena `event.context.locale`, `event.context.getDictionary(name)` y `event.context.t`, y establece `Content-Language` a menos que `setHeader` sea `false`. Se aplican todas las [opciones de detección de locale](../guide/locale-detection.md#options), y `custom` recibe el evento de h3.

::: warning Versión
Desarrollado y probado con h3 `>=1.8 <2`. h3 2.x tiene una API distinta y todavía no es compatible.
:::

## Buenas prácticas

- Pasa `{ ...dialex }` de `dialex.generated.ts` al adaptador. Lleva los diccionarios y la configuración de locales, así que `defaultLocale`, `locales` y `fallbacks` se escriben una sola vez, en `dialex.config.ts`.
- En Nuxt y Nitro pon el middleware en `server/middleware/`, para que se ejecute en cada petición antes de las rutas de API y los renderizadores.
- Usa `event.context.t("home.title")` para cadenas sueltas y `event.context.getDictionary("home")` cuando necesites varias claves, de modo que las búsquedas compartan un locale resuelto.

## Solución de problemas

- **`event.context.getDictionary` es undefined**: el archivo de middleware no está en `server/middleware/`, o no exporta un manejador por defecto.
- **h3 2.x no está soportado**: el adaptador apunta a h3 1.x (Nitro 2 y Nuxt 3/4). Comprueba la versión de h3 que instala tu framework.
- **`[dialex] Dictionary "x" not found`**: el diccionario no está en `dialex.generated.ts`. Ejecuta `dx generate` y comprueba que `include` en `dialex.config.ts` coincide con el archivo.
